# Theory-to-Paper Application Protocol

## 1. Diagnose the intended role

Choose one or more roles and explain the choice:

- `descriptive`: organizes features of the object;
- `explanatory`: proposes why an outcome occurs;
- `interpretive`: supplies concepts for reading meaning or practice;
- `critical`: reveals assumptions, power, exclusions, or contradictions;
- `normative`: evaluates what ought to be;
- `generative`: creates new questions or propositions.

Do not promise causal explanation from a theory used only as an interpretive vocabulary.

## 2. Test fit

Create a theory–study alignment table:

| Dimension | Theory | User's study | Fit/gap | Required adjustment |
|---|---|---|---|---|
| Problem | | | | |
| Unit of analysis | | | | |
| Level of analysis | | | | |
| Context/scope | | | | |
| Key concepts | | | | |
| Mechanism/interpretive move | | | | |
| Evidence type | | | | |
| Method | | | | |
| Outcome/contribution | | | | |

Reject or qualify the theory when alignment requires redefining its core concepts beyond recognition.

## 3. Design the literature review

Prefer a problem-driven architecture:

1. establish the research problem and stakes;
2. synthesize what existing approaches explain;
3. identify a specific tension, omission, or unresolved mechanism;
4. introduce the focal theory as a justified response;
5. discuss competing interpretations and limitations;
6. state how the study will use, test, extend, combine, or critique it.

For each paragraph, identify its job, key claim, supporting sources, disagreement, and transition. Do not turn the review into a chronological catalogue unless genealogy is the research question.

## 4. Build the theoretical framework

Include:

- definitions tied to sources;
- selected theoretical version and reason for selection;
- concepts retained, modified, or excluded;
- relationships or interpretive sequence;
- scope and boundary conditions;
- rival explanations or lenses;
- link from theory to data/material and method;
- expected contribution.

Make modifications explicit. Never present an analyst-created hybrid as the original theory.

## 5. Derive questions, propositions, or hypotheses

Match form to epistemology:

- use research questions for exploratory or interpretive work;
- use theoretical propositions for conceptual relationships not yet operationalized;
- use hypotheses only when variables, direction, population, conditions, and test design justify them;
- use sensitizing questions or coding dimensions for qualitative analysis when prediction is inappropriate.

For each item, provide the theoretical derivation, evidence needed, disconfirming observation, and boundary condition.

## 6. Operationalize or sensitize

For empirical designs, create:

| Concept/construct | Definition | Observable implication | Indicator/code | Data source | Rival reading | Limitation |
|---|---|---|---|---|---|---|

Avoid proxy substitution: an easy measure is not automatically the theoretical construct. For interpretive studies, replace indicators with textual, discursive, visual, institutional, spatial, or practice-based evidence cues.

## 7. Specify contribution paths

Use one or more precise verbs:

- apply in a new context;
- test a mechanism or boundary;
- refine a concept;
- extend the level or scope;
- integrate compatible theories;
- adjudicate rival accounts;
- expose a limitation or normative assumption;
- reconstruct a misread or oversimplified tradition.

State what would be new relative to the reviewed literature and what evidence would justify the claim.

## 8. Explain the user's case

When the user supplies a case, do more than map concepts onto features. Specify:

- the result, contrast, practice, or meaning to be explained;
- the unit and level of analysis;
- each actor's or material's theoretical position;
- the resources, capacities, meanings, or constraints that matter;
- the mechanism, key bargain, relation, or interpretive move;
- how choices, meanings, authority, costs, risks, or outcomes change;
- the evidence needed and what would challenge the account;
- a rival explanation, counterfactual, or alternative reading;
- the theory's boundary and what remains outside it.

Use a causal chain only for theories that warrant causal or mechanism claims:

`outcome difference → theoretical position → resources and constraints → mechanism → changed choice set → outcome and distributional effects`

For interpretive, critical, genealogical, or normative work, use:

`text/practice → conceptual location → interpretive operation → meaning or power relation revealed → alternative reading → boundary`

If the user has not supplied a case, retain an adaptable application frame and state `尚未提供研究案例`; do not invent a case or present a placeholder as an empirical finding.

When a concrete case is supplied, use [theory-to-case-lab-protocol.md](theory-to-case-lab-protocol.md) and the localized Case Lab template. A diagram may summarize the completed reasoning but cannot substitute for the prose mechanism, evidence plan, rival account, or boundary statement.
